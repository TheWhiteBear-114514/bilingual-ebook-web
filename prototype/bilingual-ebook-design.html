0 · 项目概览

本系统是一款面向语言学习者的「一键式双语阅读伴侣」Web 应用：用户上传单语种电子书（.txt / .epub / .pdf 文本型），指定目标语言，系统自动完成解析 → 分句 → 翻译 → 逐段上下对照排版 → 生成双语 EPUB / PDF 全流程，用户可直接在线阅读并下载成品。

纯响应式 Web多翻译引擎可切换（BYOK）官方 API 免密钥翻译（积分）逐段上下对照EPUB + PDF 双导出简单注册登录积分体系 + 签到用户反馈公告栏 + 管理控制台（v1.3）自有云服务器 + 域名部署

1 · 需求确认清单

决策点最终结论

2 · 技术选型

层级选型选型理由 / 备选
后端框架Python 3.11 + FastAPI原生 async 适合 IO 密集（翻译调用、文件流）；自动产出 OpenAPI 接口文档（/docs），接口文档交付物「白送」；类型提示对 AI 编程友好。备选 Flask（更简单但无自动文档）
前端框架Vue 3 + Vite + Element Plus + Pinia组件库自带上传、表单、步骤条、轮询所需的成熟组件；移动端自适应用 CSS 媒体查询 + 流式布局，无需 uni-app 跨端开销。备选 React + Ant Design
数据库SQLite（FastAPI 侧用 SQLAlchemy 2.x ORM）单文件零部署，2 人课设并发量完全够用；后续换 MySQL 只需改连接串。
认证JWT（PyJWT + passlib/bcrypt）无状态，前端存 localStorage；登录态 7 天有效，刷新令牌可选。
文件解析txt：内置 open()；epub：ebooklib；pdf：pdfplumberpdfplumber 对文本型 PDF 的段落还原质量优于 PyPDF2；扫描型 PDF 检测后明确报错，不承诺 OCR。
翻译引擎自研 Translator 抽象层，内置百度 / 有道 / DeepL 三个适配器统一 translate(text, src, tgt, keys) → str 接口；Provider 与密钥均由用户请求指定并携带（BYOK：用户密钥即用即弃、不落地；官方引擎为平台自有密钥，仅存 system_config、不下发前端）；限流、重试策略收敛在一处。
电子书生成EPUB：ebooklib；PDF：reportlabEPUB 本质是 HTML+OPF 压缩包，实现简单且移动阅读体验好；reportlab platypus 流式排版适合「原文段→译文段」的线性结构，中文字体注册 Noto Sans CJK。
前端 HTTPAxios拦截器统一处理 JWT 注入与 401 跳转。
工程化Docker Compose（api + nginx 两个服务）一键部署到云服务器，本地开发 uvicorn --reload + vite dev。
翻译引擎接入机制（v1.2 BYOK，与原型交互一致）：① GET /api/engines 返回引擎目录（名称 / 所需密钥字段 / 支持语言对），驱动前端引擎下拉框与密钥输入区的动态渲染；② 用户自行在引擎官网免费申请 API Key 并在页面填写（平台不提供任何密钥）；③ 生成请求 POST /api/books 携带 engine + engine_keys，服务端以最小请求预校验密钥有效性：缺失 / 无效 → 返回 3001「引擎未接入，不可翻译」并拒绝；④ 密钥仅 HTTPS 传输、不落日志、不入库（即用即弃）。BYOK 使平台不占任何翻译额度，切换引擎零代码改动，这是「多种兼容」的核心设计。

3 · 系统架构

整体为「Nginx 反代 + FastAPI 单体服务 + SQLite + 文件目录」的轻量三层结构，业务按 6 个模块内聚划分；翻译调用通过抽象层解耦第三方引擎。

说明：数据流单向 —— 上传文件落盘并登记 books → 解析为纯文本 → 切分为 segments → 逐个查缓存/调翻译 → 排版生成 EPUB 与 PDF 落盘 → books.status=ready → 前端展示并下载。

5 · 核心流程（上传 → 双语成品）

关于同步处理的取舍：课设书规模（≤500 页）下同步链路足够，实现简单、无队列组件依赖。前端以「步骤指示器 + 预计耗时」缓解等待焦虑；Nginx 与 uvicorn 超时均放宽至 5 分钟。若后续书籍规模上升，架构中已预留 Celery + Redis 异步化改造点（接口形态不变，仅上传后返回 book_id 轮询）。

6 · 接口设计（RESTful）

Base URL：https://<域名>/api　鉴权：除注册/登录外均需在 Header 携带 Authorization: Bearer <JWT>　统一响应包裹：{ "code": 0, "message": "ok", "data": ... }

POST/api/auth/register注册（公开）

请求（JSON）：{ "email": "a@b.com", "password": "至少6位", "nickname": "可选" }

响应 data：{ "token": "JWT", "user": { "id": 1, "email": "a@b.com", "nickname": "A" } }

错误：409 邮箱已注册　400 参数不合法

POST/api/auth/login登录（公开）

请求：{ "email", "password" }　响应 data：{ "token", "user" }

错误：401 邮箱或密码错误

POST/api/books上传并生成双语书（核心接口）

请求（multipart/form-data）：file（≤10MB，.txt/.epub/.pdf）；target_lang（需被所选引擎支持）；title（可选，缺省取文件名/书内标题）；engine（baidu|youdao|deepl|official）；engine_keys（JSON 字符串，字段名随引擎而定，见 GET /api/engines；缺失/无效 → 3001）

响应 data（同步完成后返回）：

{
  "id": 42,
  "status": "ready",              // pending | ready | failed
  "title": "Pride and Prejudice",
  "source_lang": "en", "target_lang": "zh",
  "segments": 1204,
  "failed_segments": 2,           // 翻译失败保留原文的段落数
  "epub_url": "/api/books/42/download?format=epub",
  "pdf_url":  "/api/books/42/download?format=pdf",
  "created_at": "2026-09-27T10:00:00Z"
}

错误：400 格式不支持　413 文件超过 10MB　422 扫描型 PDF 无法提取文本 / 目标语言不受支持　422 (3001) 引擎未接入 / 密钥无效

GET/api/books我的书架（历史生成记录）

查询参数：page（默认 1）、size（默认 12）

响应 data：{ "total": 8, "items": [ book 对象，同上传响应 ] }（按创建时间倒序）

GET/api/books/{id}/download?format=epub|pdf下载双语成品

校验：book 属于当前用户且 status=ready；返回文件流，Content-Disposition: attachment; filename="书名-中英对照.epub"

错误：404 不存在/无权访问　409 尚未生成完成

GET/api/engines引擎目录（v1.1 新增 · 公开，驱动前端下拉框与密钥输入区动态渲染）

响应 data：

{ "default": "baidu", "engines": [
  { "id": "baidu", "name": "百度翻译",
    "key_fields": [ {"k":"app_id","label":"App ID","type":"text"},
                    {"k":"app_key","label":"App Key","type":"password"} ],
    "src_langs": ["en","ja","ko","fr","de","zh"],
    "tgt_langs": ["zh","en","ja","ko","fr","de"] },
  { "id": "youdao", "name": "有道智云", "key_fields": [ {"k":"app_key",...}, {"k":"secret_key",...} ], ... },
  { "id": "deepl",  "name": "DeepL",    "key_fields": [ {"k":"api_key",...} ], ... }
] }

前端按 key_fields 动态渲染输入框（对应原型切换引擎时输入区联动变化的交互）。

GET/api/languages?engine=baidu指定引擎支持的语言对（query 缺省为服务端默认引擎）

响应 data：{ "engine": "baidu", "source_langs": ["en","ja","ko","fr","de","zh"], "target_langs": ["zh","en","ja","ko","fr","de"] }（前端切换引擎后重新拉取，联动刷新目标语言下拉框）

POST/api/books/{id}/retry对 failed 的书重新生成（可选接口，低成本加分）

复用已解析的分段，仅重跑失败单元并重新导出。请求：可选 target_lang 变更。

GET/api/notices公告列表（v1.3 新增 · 公开，驱动用户端首页公告栏）

响应 data：[ { "id": 1, "title": "计划维护：…", "type": "maintenance", "body": "完整正文（用户端点击条目时弹窗展示）", "date": "2026-09-27 18:30" } ]（仅启用中的公告、按发布时间倒序；type 为预设值或管理员自定义值，前端按预设值上色、自定义值用中性色）

表一览（11 张，与 database.sql 一一对应）

表分类关键字段 / 约束说明
users核心id、email UNIQUE、password_hash、points、role CHECK(user/admin)、is_active、ban_reason用户与管理员；积分余额为冗余列
books核心user_id FK、source_ext CHECK、engine CHECK(4 引擎)、status CHECK(4 态)、source_path、char_count、progress、cached_segments、finished_at任务主表；带源文件路径以便重试
segments核心book_id FK、seq、is_failed、UNIQUE(book_id, seq)逐段原文与译文
translation_cache缓存source_hash（32 位 MD5）、src_lang/tgt_lang、engine、UNIQUE(4 元组)松耦合；按引擎分键，避免跨引擎复用
point_logs积分user_id FK、delta ≠ 0、balance_after、type CHECK(8 类)只增不改的积分流水
checkins积分user_id FK、checkin_date、UNIQUE(user_id, checkin_date)每日签到，防重复
system_config积分key PK、value签到 / 注册 / 兑换比例 / 风控阈值 / 官方密钥
feedbacks反馈user_id FK、type CHECK、status CHECK(pending/done)、reward用户反馈与处理结果
risk_alerts风控user_id FK、rule CHECK(single/freq/daily)、status CHECK、resolve CHECK(unban/confirm)命中规则→自动封号→人工复核
notices独立type、is_active、views、updated_at（触发器维护）公告，无外键
logs独立level CHECK(INFO/WARN/ERROR)、module、message审计日志，无外键

建表要点

① books(user_id, created_at)、books(status)、books(user_id, status) 建索引，书架分页走 WHERE user_id=? ORDER BY created_at DESC；segments 的 UNIQUE(book_id, seq) 已自带索引，不再重复建索引。② 级联：books/point_logs/checkins/feedbacks/risk_alerts 均 ON DELETE CASCADE；translation_cache 与 notices/logs/system_config 不参与级联。③ WAL 模式提升并发读写。④ PRAGMA foreign_keys=ON 只对当前连接生效，应用侧必须在每个连接上执行（SQLAlchemy 用 event.listens_for(engine,"connect") 注册），否则级联删除会静默失效。⑤ 全部枚举字段加 CHECK 约束，非法状态在入库前即被拒绝。⑥ notices.updated_at 由 AFTER UPDATE 触发器自动维护。⑦ 缓存以 (source_hash, src_lang, tgt_lang, engine) 为唯一键——不同引擎译文质量不同，不可跨引擎命中。

官方 API 密钥说明：官方 API 密钥存于 system_config（服务端持有，不对外展示、不下发前端），与 BYOK 用户密钥（即用即弃、不落地）不同——官方密钥是平台自有资产，用于支撑「消耗积分免密钥翻译」能力，管理端「API 接入」窗口可配置但值不返显。

v1.6 相对 v1.5 的修正：取消独立 points 表（统一为 users.points 冗余列 + point_logs 流水）；补齐 risk_alerts 表；统一 feedbacks.status 为 pending/done、积分说明字段为 description、签到日期为 checkin_date；books 新增 source_path / char_count / progress / cached_segments / started_at / finished_at；translation_cache 新增 engine。

维度设计

10 · 部署方案（自有云服务器 + 域名）

部署拓扑

互联网用户 ──HTTPS(443)──▶ 云服务器 (Nginx)
                              ├─ /          → 前端静态文件 (Vue3 构建产物 dist/)
                              ├─ /api/*     → proxy_pass http://127.0.0.1:8000  (FastAPI / uvicorn)
                              │                ├─ SQLite:  /data/app.db   (volume 持久化)
                              │                ├─ 上传:    /data/uploads  (volume 持久化)
                              │                └─ 成品:    /data/output   (volume 持久化)
                              └─ TLS 证书:    Let's Encrypt (certbot 自动续期)

docker-compose.yml：
  services:
    api:
      build: ./backend          # python:3.11-slim
      env_file: .env            # 默认引擎 / JWT_SECRET（BYOK：平台不存翻译密钥）
      volumes: [ ./data:/data ]
      expose: [ "8000" ]
    nginx:
      image: nginx:1.27
      ports: [ "80:80", "443:443" ]
      volumes:
        - ./frontend/dist:/usr/share/nginx/html:ro
        - ./data:/data:ro                # 成品文件直出
        - ./nginx.conf:/etc/nginx/conf.d/default.conf:ro
        - ./certs:/etc/letsencrypt

上线步骤（按序执行）

步骤事项注意
1注册云服务器（1核2G 即可，Ubuntu 22.04）+ 域名（约 ¥60/年），域名解析 A 记录指向服务器公网 IP预算合计 < ¥150/年
2安全组仅开放 80/443/SSH(限 IP)；安装 Docker + Docker Compose8000 端口不对外暴露
3域名 ICP 备案（服务器在国内时必做，管局审核约 7–20 个工作日）⚠️ 关键路径，建议项目启动第一周就提交，与开发并行
4部署 Nginx + certbot 签发 HTTPS 证书；配置 /api 反代与 client_max_body_size 12m证书到期自动续期
5前端 npm run build 产物挂 Nginx；后端镜像 docker compose up -d 启动健康检查 GET /api/health
6配置默认引擎，用自己申请的 API Key 走一遍全流程冒烟测试（BYOK）翻译 Key 只存在于用户请求中
7数据备份脚本：每日 sqlite3 .backup + tar /data 保留 7 天低成本保险
备案风险预案：ICP 备案周期不可控。若答辩前域名未备案完成，可临时用服务器公网 IP + 端口（如 http://1.2.3.4，Nginx 直接监听 80）完成演示，备案通过后再切换为域名 + HTTPS；接口与前端代码无需任何改动。

11 · 风险与对策

风险概率/影响对策
扫描型 PDF 上传高 / 中解析阶段检测可提取文本比例，低于阈值直接报 422「暂不支持扫描版」，需求边界在首页文案中明示
用户密钥额度耗尽 / 429 限流中 / 高BYOK 下平台无额度风险，风险在用户侧：translation_cache 复用减少 API 调用；失败退避重试 ≤3 次；单段失败回退保留原文不中断全书；生成前预校验提前提示（3001）
用户密钥无效 / 填错中 / 中生成前最小请求预校验，失败返回 3001 由前端提示「未接入」并定位到具体字段；管理端引擎管理页提供各引擎调用失败率统计辅助排查
长书同步生成超时中 / 中10MB + 500 页上限从源头控制；超时 5 分钟；架构预留 Celery 异步化改造点（仅改传输层，不动业务层）
ICP 备案延迟中 / 中第一周即提交备案；IP+端口直连作为演示兜底（见部署预案）
PDF 中文乱码/字体缺失低 / 中Noto Sans CJK 字体随镜像打包，构建期即注册，避免运行期缺字
服务器数据丢失低 / 高每日自动备份 /data（数据库+文件），保留 7 天；books 元数据可随时重新生成
